Public Packaging Catalog Taxonomy: 192 Product Pages

This reproducible snapshot classifies every public product-detail URL into one primary packaging format. It helps buyers and search systems understand catalog coverage without turning page counts into unsupported claims about sales, capacity or market share.

Direct answer

The snapshot contains 192 public product pages. A deterministic title-based classifier assigns each URL to exactly one of nine format families. The largest groups are flexible bags, films and pouches (67 pages), folding cartons and paperboard boxes (37), and labels, tags and printed accessories (36). These figures describe public URLs only.

Unit of analysis

One row equals one public HTML product-detail URL listed in the site's product manifest on 15 August 2026. The analysis does not count category pages, blog posts, news pages, image files, variants hidden inside one page or unpublished products. The title and URL remain visible in the JSON so another reviewer can inspect every assignment.

Classification method

The generator reads only each public product title and evaluates mutually exclusive rules in this order:

  1. Paper bags
  2. Mailer and shipping packaging
  3. Flexible bags, films and pouches
  4. Labels, tags and printed accessories
  5. Tubes and cylindrical packaging
  6. Rigid and gift boxes
  7. Folding cartons and paperboard boxes
  8. Containers, trays and formed packaging
  9. Commercial print and other paper components as the fallback

The first matching rule wins. For example, a title containing “paper bag” is assigned before the broader “bag” rule. A title containing “magnetic gift box” is assigned to rigid and gift boxes before the generic box rule. This priority makes the result deterministic instead of allowing an analyst to choose a category after seeing the totals.

Why the classifier uses titles

Product descriptions can mention secondary components, applications and related formats. A rigid gift box description might mention a paper bag or insert even though the page's primary item is a box. Using the public title reduces that leakage and gives every reviewer the same short input. It can still simplify hybrid products, so each JSON row retains the URL for manual review.

What the dataset does not prove

  • It is not sales or order-volume data.
  • It is not manufacturing capacity, inventory or lead-time data.
  • It is not certification, compliance, test or quality-performance evidence.
  • It is not customer, market-share, popularity or search-demand data.
  • A page count does not prove that every structure is suitable for a buyer's product or destination market.

How a buyer can use it

Use the families to locate a relevant starting point, then write a project specification. A buyer comparing cartons should still define finished dimensions, board or performance target, graphics, finishes, inserts and acceptance evidence. A flexible-packaging buyer should define product, shelf-life target, fill/seal process, route and the test method and conditions for any barrier requirement. Use the packaging specification glossary to translate the category into measurable RFQ fields.

Reproduction and updates

  1. Download the public JSON.

  4. Verify that the nine family counts sum to 192.
  5. When the public product manifest changes, generate a new dated snapshot and report the new total rather than silently overwriting the meaning of the old date.

Buyer FAQ

What does this dataset measure?

It measures public product-detail URLs and assigns each to one primary format family using a published rule.

Does it show sales, capacity or market share?

No. It is a descriptive catalog taxonomy, not commercial or operational performance data.

Can one real package fit several categories?

Yes. Hybrid structures are common. The dataset uses one primary family per URL solely to make the count reproducible.

How can the result be checked?

Inspect the public JSON rows, apply the title rules in priority order and confirm that every unique URL is counted once.
